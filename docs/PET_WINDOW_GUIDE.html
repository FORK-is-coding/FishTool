01一句话看懂：桌宠是什么

人话版：桌宠是一个「前台接待员」。她不会算账、不碰数据库、不调 B 站接口。她只做三件事：站在桌角（悬浮窗）、换表情（四张图）、把对讲机里听到的话转成一张便利贴贴出来（气泡）。她需要帮助时会去敲经理的门（主窗口）。

代码层面的定位同样朴素：一个纯 Qt 悬浮窗 + 一个 WebSocket 消费端。整个模块里没有任何一行代码读写数据库、请求 B 站、或调用业务模块 —— 这是它能被安全扩展的根本原因，也是 PR 里最不该破坏的性质。

它不做什么

不读写数据库、不调 B 站 API、不做情感分析、不生成选题。这些全在 FastAPI 那一侧。

它做什么

显示四种状态图、渲染一条气泡、三个菜单动作、把鼠标交互翻译成窗口移动与位置记忆。

因此扩展边界

「展示 + 交互 + 消费协议」是安全区；一旦要碰服务端协议、重连策略、业务数据，就先补接口与测试。

02它从哪来：谁创建、传什么、几秒出来

人话版：没有单独的桌宠启动脚本。你在命令行敲 python app.py，run_desktop() 先盖好经理室（主窗口），再把接待员（桌宠）安排到桌角。接待员一上岗就掏出对讲机，试着连后厨（8000 端口）。

# app.py:219-224
main_window = MainWindow(web_port=port)
main_window.show()
pet_window = PetWindow(ws_port=port)   # 同一个 port
pet_window.show()

构造签名只有一个参数，但有三处依赖它 —— 改签名等于同时打断三处：

调用方路径用途
统一入口app.py:223桌面版装配，正式链路
P0 验收脚本tools/verify_pet_p0.py:83真窗口 + 合成鼠标事件回归
桌面回归脚本tools/verify_desktop_regressions.py:129桌面端弹窗 / 交互回归
为什么「窗口先出来、页面后出来」？

init_ui() 先 setHtml(LOADING_HTML) 摆一个加载动画，然后 QTimer.singleShot(3000, check_and_load_web) 才开始探测。子进程若中途退出，check_and_load_web() 会立刻弹窗并附上 web_subprocess.log 末 1500 字符 —— 不会无限转圈。

03十二个零件：每个文件只管一件事

人话版：这不是一个大文件，而是十二个小盒子。盒子上都写着「我只负责什么」。你要加功能，先想清楚该往哪个盒子里放 —— 放错盒子就会出现「改一个按钮崩三个测试」。

__init__.py
104 行 · 组装 + 说明书

类定义只有 pass，靠继承把六个混入拼成 PetWindow；文件头的 docstring 就是协议说明书（消息格式写在里面）。__all__ 决定外部能 import 什么。

base.py
232 行 · 窗口与状态机

建窗（无边框 / 置顶 / 透明 / 150×150）、摆图片与气泡标签、加载素材、set_state()。整个模块最核心的盒子。

drag_mixin.py
184 行 · 手感

悬停放大、长按 100ms、位移 6px 阈值、拖拽移动、松手存位置、单击开菜单、双击打日志。

ws_thread.py
167 行 · 对讲机

QThread 里跑 websocket-client，注册四个回调，发 Qt 信号；连接成功再起一个 daemon 心跳线程（30 秒一次）。

menu_mixin.py
101 行 · 三张卡片

菜单懒创建、淡入 + 上滑动画、右侧优先 / 左侧翻转定位、三个按钮的接线。

ws_mixin.py
78 行 · 翻译官

建线程、桥接 4 个信号、把 JSON 字典按 type 分流（alert / toast）。

notify_mixin.py
77 行 · 便利贴

显示 / 隐藏气泡、单一 5 秒定时器、点别处收菜单（装在 QApplication 上的 eventFilter）。

image_label.py
70 行 · 画笔

等比平滑绘制，scale_factor 属性可被动画驱动，值夹在 1.0–1.08。

lifecycle_mixin.py
50 行 · 下班流程

关窗时依次：收菜单 → 停定时器 → 摘 eventFilter → 停 WS → 等 5 秒 → 接受关闭；退出代理转交主窗口。

menu_panel.py
38 行 · 卡片本体

固定 236×176 的无边框 QFrame，三个按钮：打开主面板 / 舆情预警实况（占位）/ 关闭程序。

assets.py
33 行 · 找素材

三级候选目录（exe 解包目录 → exe 同级 → 仓库根）+ 共享 logger。

runner.py
24 行 · 旁门

独立进程跑桌宠的入口，主流程没用到；单独跑时找不到主窗口，两个动作只会 warn。

04乐高式拼装：混入（Mixin）是怎么叠起来的

人话版：PetWindow 自己没有身体，它由六块乐高叠出来。越靠左的块优先级越高 —— 两块都想回答同一个问题（比如「鼠标松开了怎么办」）时，左边的赢。

05四张脸：状态机里有一个是死的

人话版：文件里定义了四种表情，但代码从来没用过「点击」那张 —— 它是上一版留下的空壳。真正的「图」只有待机、拖拽两张，通知态只有一颗粉色圆点占位。

常量值谁设置它素材现状
STATE_IDLE0初始化、连接成功、松手、气泡隐藏assets/待机.png在用
STATE_DRAGGING1长按到期 / 位移超阈值assets/拖拽.png在用
STATE_CLICKED2——仅占位圆死代码
STATE_NOTIFY3show_notification()仅占位圆半成品

set_state() 的契约很短但要记牢：值不在 self.images 里就静默忽略。所以新增状态必须四处齐改：常量 → images 字典 → load_placeholder_images() 的素材与兜底 → 测试宿主的 STATE_* 属性。

06手感：四个数字决定它像不像活的

人话版：为什么「单击是开菜单、拖动是搬家」不会打架？靠三个阈值分工：按下去先观察 100 毫秒，手指挪动超过 6 像素才算拖，鼠标移入 160 毫秒慢慢放大。

07对讲机协议：两条管道、两种听众

人话版：对面只有两种喊话：alert（业务预警，有异常评论）和 toast（系统错误，谁出错弹谁）。桌宠两种都听；网页只听得懂 toast。你新加一种喊话不会被网页骂，它直接忽略。

字段对照：alert 少了一个 title

typedata 字段来源桌宠怎么用
alert bvid, video_id, type, level, message, details, created_at modules/comment/_alerts.py:283 取 title 拿不到 → 标题永远是「新通知」；正文取 message
toast title, message, level, source, error_code core/toast.py:54 标题、正文都有；message 为空直接丢弃
其他 —— —— 静默忽略（pong 也走这条）
握手时还有一道门：Origin 校验

服务端在 accept() 之前检查 Origin，跨站来源直接 close(1008)（web/main.py:787）。当前桌宠用的 websocket-client 不带 Origin，所以放行。如果你换成带 Origin 的客户端、或加了自定义握手头，就可能被自己的服务拒之门外。

08三个接缝：外部世界只从这里进来

人话版：桌宠和外界只有三根绳子：一根连着对讲机（WebSocket），一根连着经理室的门把手（鸭子类型方法名），一根贴着便利贴（QSettings）。断哪根，哪块功能就哑。

接缝 1 · WebSocket
ws://localhost:{port}/ws

只收 alert / toast；只发 ping。端口来自构造参数，与主窗口共用同一个 port。
改协议要同时看服务端与网页。

接缝 2 · 鸭子类型
hasattr(widget, "show_window")

打开主面板找 show_window()；退出找 quit_application()。没有信号、没有注册表、没有接口类。
任何同名方法的窗口都会被误命中。

接缝 3 · QSettings
BiliOpsToolbox / DesktopPet

只存一个键 position（QPoint）。注册表路径 HKCU\Software\BiliOpsToolbox\DesktopPet。
新增配置请加新键，不要复用 position。

09扩展雷达：A 级随便改、C 级先设计

人话版：绿色三件事今天就能动手，改完不碰别人；黄色要先写测试；红色会牵动服务端协议，独立开 PR，先出设计。

A 级 · 低风险 只动展示与本地逻辑

#改什么落点为什么安全
A1气泡改纯文本 / 标题正文分开；alert 无 title 时按 level / type 映射中文标题notify_mixin.py只影响渲染，不动协议
A2恢复位置时校验是否仍在可用屏幕上，越界回落右下角base.py:142只多一次几何判断
A3补齐 点击.png / 通知.png 素材，仍以占位圆兜底；或明确删除死状态base.py:150 + assets/字典驱动的既有机制
A4清掉重复定义的 colors 字典、噪声注释base.py:165/174纯清理，行为不变
A5新配置走 PetSettings 适配器，键名前缀避开 position新文件 + base.py与旧配置共存

B 级 · 中风险 要动线程 / 动画，先补测试

#改什么注意
B1断线自动重连（1s→30s 指数退避），心跳线程句柄化并在 stop() 里 join必须在 closeEvent 的 wait(5000) 语义内退出；重连期间不能堆积心跳线程
B2离线视觉态（半透明 / 灰化，或新增 STATE_OFFLINE）新状态要同步 images + set_state 校验 + 测试宿主
B3跨屏拖动后按新屏可用区重新夹住；菜单定位复用 screenAt()别改 _sync_menu_position 的「右侧优先→翻左→夹住」三段式

C 级 · 高风险 牵动服务端与协议

#改什么为什么危险
C1把「舆情预警实况（待更新）」接上真实数据现在是纯 QToolTip 占位；接数据需要新 API 或新推送 type，且要定「谁能看、看多少」
C2定向推送（只发给桌宠）ConnectionManager 现在是全局广播、无 client_id；加频道会同时影响浏览器客户端
C3多桌宠实例 / 独立进程常驻没有实例身份与关闭策略；run_pet_window() 单独跑时找不到主窗口

10坑清单：改之前先知道哪里会咬人

人话版：下面每一条都是代码里真实存在的薄弱点，不是我猜的。A 级 PR 顺手带走几条，评审会觉得你很懂这个模块。

高
没有重连服务重启、网络抖动后桌宠永久离线，只留一行 warning。注释写着「显示离线状态」，实际没有任何视觉变化。→ B1 + B2 一起做，一次 PR 收口
高
气泡走 Qt 富文本且未转义setText("<b>{title}</b><br>{message}")，而 message 可能来自评论内容 / 关键词命中，含 < 会被当标签解析掉。→ A1，一行 setTextFormat(Qt.PlainText) 起步
中
alert 没有 title 字段业务预警永远显示「新通知」，用户看不出是「评论量突增」还是「风险关键词」。→ A1，按 type / level 做映射表
中
心跳线程无句柄每次 on_open 新建一个 daemon 线程，没有保存引用；一旦加重连，旧线程可能残留并发 send。→ B1，存 self._heartbeat_thread 并在 stop() join
中
位置恢复不校验屏幕拔掉副屏后，注册表里的坐标可能落在屏幕外，桌宠「消失」，用户以为坏了。→ A2，十分钟的改动
中
消息没有结构校验data 不是 dict、字段不是字符串时，show_notification 里的 .get() 会抛异常；虽然 Qt 槽里异常不一定崩，但这条消息就丢了。→ 加 isinstance 与 str() 兜底
低
STATE_CLICKED 是死状态定义、占位图、文档都写了，但没有一个调用点。→ A3 二选一：接上或删掉
低
colors 字典重复定义同一个函数里写了两遍，后一份生效，前一份是死代码。→ A4
低
鸭子类型单例假设靠 topLevelWidgets() + hasattr 找主窗口，多个窗口有同名方法时行为不确定。→ 若加窗口，命名避开这两个方法
低
素材只覆盖两态通知态是粉色圆点，跟整个 UI 设计语言脱节。→ A3

11PR 纪律：怎么改才不返工

人话版：这个模块有 18 条测试 + 2 个可视化验收脚本盯着。按下面的清单走，你提的 PR 基本不会被要求重写。

必须做

  • 新混入放 desktop/pet_window/xxx_mixin.py，类名 XxxMixin，在 __init__.py:78 的基类列表按依赖顺序插入
  • 同步更新 tests/test_desktop_pet_ui.py 的 _PetHost 基类列表与属性桩
  • 新增状态四处齐改：常量 → images → load_placeholder_images → 测试宿主
  • 新消息类型只在 ws_mixin.on_ws_message 加 elif，字段做类型兜底，未知类型静默忽略
  • 日志统一用 .assets.logger，中文消息 + %s 惰性格式化
  • 定时器一律 QTimer(self) + setSingleShot(True)，关闭时 stop()
  • 素材放 assets/ 根目录，缺失必须回落占位图
  • Qt 事件回调里包 try/except + logger.exception

不要做

  • 不要改 PetWindow(ws_port=...) 签名（三处依赖）
  • 不要把 setup_websocket 逻辑搬进 __init__（会打掉 OfflinePetWindow 离线技巧）
  • 不要改窗口 flags（Tool 决定不进任务栏）
  • 不要在 QThread.run 里碰 QWidget
  • 不要在事件回调里抛异常（会带走整个窗口进程）
  • 不要往 requirements.txt 加新第三方依赖
  • 不要把「接真实预警数据」和渲染优化混进同一个 PR

提交前自检（cmd，set 的引号不能省）

cd /d D:\\FishTool
set "QT_QPA_PLATFORM=offscreen"
.venv\Scripts\python.exe -X faulthandler -m pytest tests/test_desktop_pet_ui.py tests/test_desktop_websocket.py tests/test_desktop_dpi_scroll.py -q
.venv\Scripts\python.exe tools\verify_pet_p0.py
.venv\Scripts\python.exe tools\verify_desktop_regressions.py
为什么引号不能省？写成 set QT_QPA_PLATFORM=offscreen && ... 时，& 前面的尾空格会被并进变量值，Qt 解析平台插件名失败直接以 0xC0000409 崩掉进程 —— 这是解释器级崩溃，try/except 拦不住。仓库里已经踩过一次，记录在 docs/TEST_BASELINE_AND_DESKTOP_RUNBOOK.md §3。
